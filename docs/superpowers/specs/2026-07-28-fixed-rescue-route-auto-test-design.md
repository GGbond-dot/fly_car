# 固定搜救路线独立飞行测试设计

## 目标

新增一个飞车侧独立测试 launch。它不依赖 AI Agent、Web、地面车或跨机 UDP，
启动后等待一段可配置时间，自动加载当前“开始搜救”语音任务使用的完整固定路线，
用于单独验证飞车的定位、地面行驶、起飞、空中遍历、返航和降落链路。

遥控器飞行开关继续作为硬件起飞门。软件可以提前进入空中航点，但操作者未拨动
开关时飞车不会真正起飞。

## 非目标

- 不启动或调用 `terminal/`、LLM、语音识别和 Web 控制台。
- 不经过车端 `xmachine_bridge`，也不要求地面车在线。
- 不执行难民识别、语音确认、物资投放或动态禁飞区规划。
- 不修改正式任务入口 `patrol_ground.launch.py` 的行为。
- 不改变 PID、串口、地空仲裁或航点到达算法。

## 方案

新增 `my_launch/launch/fixed_rescue_route.launch.py`，直接复用现有飞车执行链：

```text
fly_carto
  → map←laser_link TF
  → route_test_node（预装固定路线）
  → /target_position
  → chassis_mux
      ├─ 地面：diff_drive_controller → chassis_bridge → SR5E1E3
      └─ 空中：position_pid_controller → uart_to_stm32 → 飞控
```

launch 启动时立即启动 Cartographer，并设置 `ROS_DOMAIN_ID=1`。等待默认 8 秒后，
再启动地面底盘、UART、位置 PID 和预装航点的 `route_test_node`。因此不需要额外
publisher 节点，也不需要通过 `/wildlife/waypoints` 跨机下发。

延时暴露为 `start_delay_s` launch 参数，默认值为 `8.0`。

## 固定路线

航点使用飞车本地 `map` 坐标，单位依次为 `cm, cm, cm, deg`。路线与当前
`terminal/src/patrol/planner.py` 在语音默认任务、`heading_mode=follow`、
巡航高度 100 cm 时生成的路线一致：

| 地面起点 | 0 | 0 | 0 | 0 |
| 地面起飞点 | 300 | 0 | 0 | 0 |
| 原地升高 | 300 | 0 | 100 | 0 |
| 原地转向 | 300 | 0 | 100 | -90 |
| 巡航 | 300 | -300 | 100 | -90 |
| 巡航 | 300 | -375 | 100 | -90 |
| 原地转向 | 300 | -375 | 100 | 180 |
| 巡航 | 200 | -375 | 100 | 180 |
| 原地转向 | 200 | -375 | 100 | 90 |
| 巡航 | 200 | -250 | 100 | 90 |
| 原地转向 | 200 | -250 | 100 | 180 |
| 巡航 | 100 | -250 | 100 | 180 |
| 原地转向 | 100 | -250 | 100 | -90 |
| 巡航 | 100 | -375 | 100 | -90 |
| 原地转向 | 100 | -375 | 100 | 180 |
| 巡航 | 41 | -375 | 100 | 180 |
| 原地转向 | 41 | -375 | 100 | 90 |

## 启动接口

默认运行：

```bash
ros2 launch my_launch fixed_rescue_route.launch.py
```

修改启动延时：

```bash
ros2 launch my_launch fixed_rescue_route.launch.py start_delay_s:=12.0
```

launch 在控制台打印固定路线用途、延时和安全提示。路线执行一次，完成降落后保持
最后一个航点，不自动循环。

## 安全行为

- 飞车必须按正式搜救任务相同的起点和朝向摆放；路线已经是飞车本地 `map` 坐标，
  不再经过场地坐标转换。
- `chassis_mux` 继续依据航点 z 在地面链与空中链之间互斥切换。
- 遥控器飞行开关未拨动时，飞控硬件门阻止实际起飞。
- launch 不提供循环模式，防止任务完成后意外重新执行。
- 本地开发机不执行 `colcon build`；最终编译和实飞验证必须在开发板进行。

## 测试

新增 launch 级 Python 测试，导入 launch 文件并验证：

1. 固定航点数量和扁平数组长度正确。
2. 地面起点、起飞点、巡航关键拐点、返航点和降落点顺序不变。
3. 原地升高和原地转向航点被保留。
4. 默认延时为 8 秒，且可以通过 launch 参数覆盖。
5. 路线不循环，并且不包含 AI Agent、Web、UDP bridge、YOLO 或投放节点。

开发板验证按以下顺序进行：

1. 不拨飞行开关，确认地面段到达起飞点后不会实际起飞。
2. 拨动飞行开关，确认原地升高、转向和空中遍历顺序。
3. 确认返航到 `(0, 40)` 后垂直降落并保持末点。
